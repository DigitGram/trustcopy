# Developing TrustCopy

## How it works

The installer copies `src/` to `~/.local/share/trustcopy/`, links `~/.local/bin/trustcopy` and registers
a desktop entry and the icons. The right-click entries are small Nautilus scripts (and Nemo/Caja scripts, when installed) that `trustcopy` writes itself, named in the current language. `core.py` holds the copy engine and `desktop.py` the settings, the Nautilus scripts and the shortcuts (neither has UI code);
the `ui_*.py` modules only show it.

## Project layout

```
src/trustcopy.py     entry point; picks the window or the terminal mode
src/cli.py           the command line and the terminal mode (copy/move as text, no GTK)
src/core.py          the copy engine: verification, conflicts, pause, clean cancel (no GTK)
src/desktop.py       settings, Files right-click entries, keyboard shortcuts, restarting the file managers (no GTK windows)
src/ui_gtk.py        GTK 4 / libadwaita application and command line
src/ui_panel.py      the job window (graph, bars); ui_files.py the file list window; ui_settings.py the settings window
src/ui_graph.py      the speed graph: drawing and speed maths (pure cairo)
src/ui_dialogs.py    conflict and warning dialogs; ui_common.py constants, formatters, result summary
src/ui_about.py      artwork of the About dialog (ui_about_art.py)
src/i18n.py          tiny gettext replacement that reads po/*.po directly
po/                  translations (trustcopy.pot is the template)
data/                desktop entry, icons
install.sh           per-user installer and uninstaller
tests/test_core.py   checks for core.py, desktop.py, i18n.py and the translations
tests/smoke_gtk.py   opens the progress window on a real copy and checks that the bars are laid out
tests/scenarios.sh   sandbox to try every dialog by hand (conflicts, errors, bad checksum, full disk)
tests/install_test.sh  installs into a throw-away home and removes it again
```

## Tests

```sh
pip install pyflakes && pyflakes src tests
python3 tests/test_core.py
xvfb-run -a python3 tests/smoke_gtk.py   # needs xvfb; the test keeps off your screen, session bus and settings
```

The same checks run on every push via GitHub Actions (`.github/workflows/test.yml`): once on Ubuntu 24.04 (GTK 4.14,
the oldest supported) and once in an Ubuntu 26.04 container (newer GTK and Python lay out and behave differently).

## Try it yourself

```sh
tests/scenarios.sh
```

builds a throw-away folder `/tmp/trustcopy-test` (nothing outside it is touched) with name conflicts, unreadable files,
a file that gets damaged while copying and more, and prints what to do in Files to see each dialog.

## Translating

Translations are plain gettext `.po` files in `po/`, read directly at runtime (no `msgfmt` step).
English source strings are the message ids; missing entries fall back to English. German is maintained
by the author; all other translations were generated by an AI assistant and have not been reviewed by native speakers,
so corrections are very welcome.

```sh
cp po/trustcopy.pot po/fr.po     # then translate the msgstr lines, e.g. with Poedit
python3 tests/test_core.py       # checks every .po against the strings used in the code
```

After changing strings in the code, refresh the template and merge it into the translations:

```sh
xgettext --from-code=UTF-8 --language=Python -k_ -kN_ -k_n:1,2 --add-comments=TRANSLATORS --add-location=file \
         -o po/trustcopy.pot src/*.py
for po in po/*.po; do msgmerge -U --no-fuzzy-matching --backup=none "$po" po/trustcopy.pot; done
```

A language shows up in the settings as soon as its `.po` file exists; add its native name to
`NATIVE_NAMES` in `src/i18n.py` if you want more than the language code listed.
